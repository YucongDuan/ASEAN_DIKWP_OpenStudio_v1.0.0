## 从报告到学生自己的作品

这不是另一个仓库链接页面。系统把“理解一种方法”和“解决自己的问题”接起来：

**提出自己的问题 → 学习概念与案例 → 选择并比较仓库 → 改动输入开展实验 → 记录继承与创新 → 导出可运行作品 → 取得教师反馈或继续贡献。**

主张、数据、语境、知识、价值权衡和目的在同一份作品档案中保持关联。学生可以跳过已掌握的内容，也可以从原报告的任何研究主题进入。平台不规定完成天数或强制项目日程。

## 运行

### 离线学习：解压后直接打开

打开 `OpenStudio_Offline.html`。学习、检索、实验、作品编辑和导出都在浏览器本地完成，不需要Python、账号、API密钥或联网。首次打开可能被聊天附件预览器禁止脚本，请先下载到本机再用浏览器打开。

浏览器允许存储时，草稿保存在本机浏览器。隐私模式、禁用本地存储或清理浏览器数据可能使存档丢失；**导出的JSON/ZIP是可携带的作品副本**。浏览器提示存储不可用时立即导出。

### 本地账户与课堂

在完整源码包目录运行：

```bash
python server.py
```

浏览器打开 `http://127.0.0.1:8765`。学生可用化名注册。用户名使用3—40位英文字母、数字、下划线或短横线；密码至少10字符。

教师账户由本机操作人员创建，不在网页开放自助提权：

```bash
python server.py create-teacher --username teacher
```

密码由终端交互输入。没有通用默认密码。账户和项目保存在 `instance/studio.sqlite3`。不要将该目录提交到GitHub。

`start_windows.cmd` 与 `start_unix.sh` 提供启动入口。本地服务只监听回环地址；学院共享服务器使用 `app.wsgi:application` 配合自己的HTTPS与WSGI服务，详见部署说明。无需把开发服务器直接暴露公网。

## 一个可以直接演示的学生问题

> 我想核对中文和越南语商品记录，知道1000 kg和1 tonne是否指向同一货量，同时保留交易目的与币种差异。

在首页选“跨境商品语义核对”示例，系统创建作品及候选组件。进入实验室运行默认输入：字面比较有差异，但单位标准化后等价。将右侧币种改为VND，或将目的改成发送报价，关键差异重新出现。学生保存实验、解释继承的DIKWP资源区分思想与自己的修改，再导出项目ZIP。

预置样例位于 `examples/cross_language_trade`：

```bash
cd examples/cross_language_trade
python experiment.py
python -m unittest discover -s tests -v
```

导出的 `experiment.py` 是平台新写的、可修改的教学程序；不是未经说明就把若干上游仓库拼成的生产系统。使用真正上游代码时，依据版本锁、许可和接口说明继续继承。

## 多语覆盖

简体中文、英语、越南语、印尼语、马来语、葡萄牙语、菲律宾语、泰语、高棉语、老挝语、缅甸语、泰米尔语、德顿语，共13个语言包。深度讲义与自测提供中文、英文、越南语；其他语言保留英文深度解释。源论文、书目、报告和仓库简介保持原始语言，不伪装成已全文翻译。语言包与三语讲义均欢迎师生按专业语境审校。

## 学院名称与内容更新

`data/site.json` 控制显示名称。可在学院确定正式名称后修改 `audience`，运行 `python scripts/build_web.py` 更新界面与离线版。系统设计面向中国—东盟多语种共创，不以当前配置宣称学院更名已经完成。

`data/catalog.json` 保留候选来源；作者正式目录快照记录483仓库、12领域、2026-09-08日期。附带候选导航承接原报告的历史480+3整理，不声称本次逐仓库重新审计。需要当前元数据时运行：

```bash
python scripts/sync_catalog.py
```

新仓库先标作元数据入口，原有课程标签和教师解释保留。网络出错时不写入不完整分页结果。

## 源码与测试

```bash
python -m unittest discover -s tests -p "test_*.py" -v
node tests/test_core.js
```

Node仅用于开发测试；浏览器和Python服务器运行不依赖Node。浏览器检查另见 `tests/browser_check.py`（开发依赖Playwright和Chromium）。精确测试记录和环境范围见 `qa/RELEASE_CHECKS.md`。
