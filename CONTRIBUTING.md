# Contribute a method, an example or a clearer explanation

Useful contributions include native-language terminology review, a new problem-specific lesson, a counterexample, a carefully pinned repository adapter, an improved baseline, accessibility fixes and clearer documentation. A small reproducible contribution is valuable.

State the problem, inherited source/commit, modification, fixed inputs, observed result and remaining questions. Keep original licenses and credit. A translation-only contribution should change labels/content, not silently change canonical concept IDs. Preserve existing input fixtures when adding new tests.

Run Python and Node tests. Rebuild the offline HTML after changing web assets or JSON. Update language coverage honestly. New catalogue records can begin as metadata-only; add teaching annotations only when their role has been examined. Do not add fake adoption, production-deployment or consciousness claims.

Do not commit `instance/`, credentials, student work or font files. Examples should use synthetic data and consenting fictional identities. Public publication and upstream pull requests remain explicit contributor actions.
